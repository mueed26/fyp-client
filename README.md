# AI Study Companion — Frontend

The client-side of the AI Study Companion, a full-stack web application built as a Final Year Project at Universiti Sains Malaysia. The frontend is a Next.js 16 application that provides the full user interface for document management, AI chat, study material generation, and AI-powered note-taking.

## Features

### Projects
Each user works inside projects (notebooks). Every project has its own documents, chats, notes, and generated study materials — all isolated from each other.

### Document Upload and Processing
Users can upload PDF, DOCX, PPTX, TXT, and MD files up to 50MB, or paste a website URL. Files are uploaded directly to S3 via a presigned URL generated by the backend. After upload, the app confirms the upload and triggers background ingestion. The UI polls for live processing status updates (Partitioning, Chunking, Summarizing, Vectorizing, Completed).

Documents can be tagged as either Lecture Notes or Past Year Paper, which enables exam-aware study material generation.

### AI Chat (RAG-powered)
Each project supports multiple chat conversations. Messages are streamed back token by token using Server-Sent Events so responses appear in real time. The chat interface shows typing indicators, tool-use status updates ("Searching documents...", "Searching the web...", "Generating response..."), and source citations (filename + page number) underneath each AI response.

### Studio (Study Material Generation)
The Studio panel lets users select documents, tag them, and generate:
- Summaries (exam-focused when a past year paper is selected)
- Flashcards (with Past Year badges on exam-linked cards)
- Practice Questions (MCQ, Short Answer, Long Answer/Essay — all with Past Year badges and difficulty labels)
- Mind Maps (interactive, drag to pan, scroll to zoom, powered by Mind Elixir)

When a past year paper is selected alongside lecture notes, the UI shows a "Past year selected — exam-aware generation enabled" banner before generation.

Generated sources can be expanded to generate more questions or flashcards, and deleted when no longer needed.

### Practice Questions (Quiz Mode)
MCQ questions are interactive — click an option to reveal if it is correct or wrong, with an explanation. Short answer and long answer questions have a free-text input with a "Submit for grading" button that sends the answer to the backend for AI grading, returning marks awarded, verdict, feedback, strengths, and areas to improve. Model answers can also be revealed.

### Flashcard Viewer
Flip-card interface showing the front (question) and back (answer) of each card, with Past Year and difficulty badges. Users can navigate through the deck.

### Notes
An independent rich-text note-taking workspace, separate from the document processing pipeline. Each note has its own AI chat assistant that reads the note's content and keeps full conversation history across sessions. Users can clear conversation history per note.

### Document Inspector
A debug/detail modal showing the full ingestion pipeline breakdown per document: Partitioning step (element counts by type), Chunking step (chunk count, average size, images per chunk), Summarizing step (progress), and a Chunks Viewer to inspect individual chunks and their content.

### Settings
Per-project RAG settings configurable from the UI:
- Embedding model
- RAG strategy (Basic Vector, Hybrid, Multi-Query Vector, Multi-Query Hybrid)
- Agent type (Simple Agent, Supervisor/Agentic Agent)
- Chunks per search
- Final context size
- Similarity threshold
- Number of queries (for multi-query strategies)
- Reranking enabled/disabled
- Reranking model
- Vector and keyword weights

## Getting Started

### Prerequisites
- Node.js 18+
- A running instance of the backend server (see the backend README)
- A Clerk account and application

### Installation

```bash
git clone <repo-url>
cd fyp-client
npm install
```

### Environment Variables

Create a `.env.local` file in the root:

```env
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=your_clerk_publishable_key
CLERK_SECRET_KEY=your_clerk_secret_key
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in
NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up
NEXT_PUBLIC_API_URL=http://localhost:8000
```

### Running Locally

```bash
npm run dev
```

The app will be available at `http://localhost:3000`.

### Building for Production

```bash
npm run build
npm run start
```
